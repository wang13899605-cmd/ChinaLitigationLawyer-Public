# 新建 Matter 工作流

## 目标

在不修改原始资料的前提下，建立一个可隔离、可追溯、可持续处理的新案件工作空间。

## 1. 建立目录

1. 先明确两个根路径：`FRAMEWORK_ROOT` 为本项目根目录；`MATTER_ROOT` 为本案工作目录。默认在 `FRAMEWORK_ROOT/08_Cases/` 新建，也可以在律师通过 `$china-litigation-workflow` 指定的其他绝对本地路径建立。
2. 无论 Matter 存放在哪里，均从实时的 `FRAMEWORK_ROOT/08_Cases/_MATTER_TEMPLATE/` 初始化，不复制或分叉整套框架。
3. 命名建议：`YYYY-NNN_简短案件名`，其中编号必须唯一。
4. 不覆盖或合并既有标准化 Matter；存在重名、编号冲突或身份不明时停止该项操作并核对。
5. 外部目录已有散放材料时，先清点，再将获准材料复制到 `MATTER_ROOT/00_Original/`；不移动、改名、改写或删除来源文件。外部目录若位于其他 Git 仓库、同步盘或权限规则不明的位置，应提示风险但不得自行上传、同步或迁移。

## 2. 完成案件身份证

填写 `matter.yaml`：Matter ID、名称、客户及地位、对方、案由/案件类型、法域、机构、程序阶段、客户目标、关键期限、提醒政策、保密等级和状态。未知字段明确使用 `null`、空数组、`unverified` 或 `unconfirmed`，不得猜测。

Matter建立时一次性询问是否授权主动期限提醒，并记录接收人、提醒方式和覆盖的期限类型。`authorized` 时，后续达到确认门槛且在授权范围内的期限可以自动创建或更新提醒；`unconfirmed` 或 `disabled` 时只维护期限台账和风险清单。

## 3. 记录律师指令

在 `LAWYER_INSTRUCTIONS.md` 记录：

- 当前委托目标与最低可接受结果；
- 特殊要求、禁区、时间要求、交付对象；
- 允许使用的材料、是否允许外部检索/云端处理；
- 如律师已按 LR-01 确认本 Matter 的处理授权，记录获准环境、材料、任务及限制；核对是否另有更严格的客户或律所要求，不将材料导入其他服务或跨案测试集；未确认前不得处理真实客户材料；
- 已知策略偏好与需避免的立场。
- 主动期限提醒的授权状态、接收人、方式和覆盖范围。

## 4. 接收原始材料

1. 先制作来源目录清单和复制计划。
2. 将获准纳入的材料复制到 `00_Original/`，保留原名与目录关系；不移动或改写来源文件。
3. 记录复制时间、来源路径和异常；条件允许时生成文件哈希。
4. 发现加密、损坏、缺页、重复、版本冲突或可疑文件时，记录后继续处理其他材料。

## 5. 初始处理

- `01_Index/`：文件清单、重复关系、版本、可读性和异常；
- `02_Extracted/`：OCR、文本提取、表格抽取等派生内容；
- `03_Facts/`：带状态和来源的事实对象；
- `04_Evidence/`：证据对象、证明目的、相反证据和证据缺口；
- `05_Law/`：经核验的法源与检索记录；
- `06_Analysis/`：争点、请求/抗辩、要件与风险分析，以及程序状态、期限台账、复算记录、变更记录、庭审信息卡和提醒登记；
- `07_Strategy/`：主位、备位与最低限度方案，重大策略需律师决定；
- `08_Drafts/`：AI 草稿或待审稿，以及按文书版本维护的 `DRAFT_REGISTER.md`；
- `09_Final/`：仅放律师确认的最终版本；
- `10_Archive/`：过期工作版本与结案归档副本。

## 6. 首轮交付

形成材料索引、已知/未知/冲突清单、关键期限、初步事项地图、下一步工作和高价值律师问题。不要因单个待定问题停止其他不受影响的工作。

同时根据诉讼地位、程序阶段、客户目标、已收到的程序文件和最近期限更新 `DOCUMENT_PLAN.md`，标明当前必需、建议、条件性和不需要的文书。对当前必需且不受律师决策门槛阻碍的文书，读取 `05_Templates/TEMPLATE_INDEX.yaml`，从匹配的 Word 母版制作待审稿；无可对照母版时适用项目默认排版。每份草稿登记于 `08_Drafts/DRAFT_REGISTER.md`，保留版本、起草依据、模板、待决事项和逐页质检结果；模板选择和版式核验按 `00_System/Rules/09_template_selection_and_fidelity.md` 执行。

## 7. 后续庭审触发

当收到开庭通知或律师上传庭审笔录、庭后说明时，读取 `01_Skills/prc-hearing-preparation-and-record/SKILL.md` 处理对应庭审周期。G4先登记并核对新通知、变更和期限；正式开庭前将庭审提纲与独立法律法规汇编列入文书计划，分别以 `TPL-HRG-002` 和 `TPL-LAW-003` 制作待审DOCX。两份文件的法条栏目逐条照录经核验的适用版本完整原文；法规汇编不写案例或适用分析，必要分析另作法律检索报告或内部备忘录。庭后仅以律师提供的材料重建事件，区分正式笔录与个人记录，更新庭审日志、后续任务、受影响分析和文书草稿；重大立场及对外提交始终由律师控制。该Skill现为`draft`，不因专业标准已确认而自动成为`validated`。

## 8. 后续任何新材料或律师决定的跨流程增量更新

在当前Matter明确收到新材料、程序通知、庭审记录、律师决定或经核验的新法律依据后，读取`01_Skills/matter-update-control/SKILL.md`。以`06_Analysis/MATTER_UPDATE_REGISTER.md`记录批次、更新前基线、冲突、影响范围、专责流程和关闭状态；证据/期限/庭审等由对应Skill处理，G14只协调选择性重跑和版本追踪。已批准或已提交/发送的文书不得原地修改，必要的补充、更正或告知交律师决定。该Skill为`draft`，首次真实Matter应用须明确指定其路径，并核查实际输出。

## 9. 涉及本金、利息、违约金、损失或费用的金额测算

按当前请求/抗辩和程序阶段读取`01_Skills/damages-interest-calculation/SKILL.md`。先在`06_Analysis/MONETARY_TRANSACTIONS.md`整理来源、字段及交易勾稽，在`06_Analysis/MONETARY_CALCULATIONS.md`冻结各情景的法律/合同参数，再使用适用且经过测试的确定性工具计算。内置脚本只支持明确设定参数的分段单利及部分付款，不决定法律口径，不能用于复利、未验证汇率、复杂损失或自动执行迟延履行利息。关键结果独立复核并与G5请求、G8文书核对；争议口径及最终金额由律师决定。该Skill为`draft`，首次真实Matter应用须明确指定路径并检查输出。
