# 如何修改一个 Skill

## 不要这样说

“帮我优化一下这个 Skill。”这会导致目标不清、规则膨胀和针对单一案件过拟合。

## 先判断改哪里

- 只影响当前案件：写入 Matter 的律师指令或决定，不改通用 Skill。
- 可复用但只适用于某一细分业务：考虑领域 Skill 或参考文件。
- 跨业务稳定成立的专业原则：才考虑修改通用 Skill。
- 只是模板格式：优先改 `05_Templates`，不一定改 Skill。
- 法律来源更新：优先更新 Public Knowledge / references 与核验日期。
- 确定性计算错误：优先修工具与测试，而不是加一段提示词。

## 标准修改指令

```text
请修改 01_Skills/[skill-name]/SKILL.md。

修改原因：[来自哪个真实 Matter、使用问题、法律变化、法院反馈或 Eval 失败]
发现的问题：[当前 Skill 的具体可观察失败]
证据位置：[相关 Matter、Eval、Gold Standard 或文件路径]
我希望达到的结果：[明确目标和验收标准]

要求：
1. 先阅读 AGENTS.md、当前 SKILL.md，以及与本次问题相关的 references、examples、tests 和 Eval；
2. 先判断问题应改 Skill、参考资料、模板、工具还是 Matter 指令，并说明理由；
3. 不修改与问题无关的规则；
4. 优先最小必要修改，不因一个个案把 Skill 过拟合；
5. 若只适用于特定案件类型，评估是否应拆成领域 Skill；
6. 不加入真实客户敏感信息；
7. 实质修改升级版本，纯错别字/链接修复可只增加补丁版本；
8. 修改前保存 Git 版本，不复制“final_v2_最终版”式文件；
9. 运行现有回归测试，并新增能复现本次失败的测试；
10. 比较修改前后 Eval，列出改善、退化和 Critical Error；
11. 新版未改善或引入重大错误时，不强行保留，建议回退或继续 testing；
12. 更新 10_Logs/skill_change_log.md；
13. 不自动 commit，不对外上传。

完成后告诉我：修改了什么、为什么改、哪些测试改善、哪些退化、是否建议保留，以及需要我决定的事项。
```

## 具体示例：修改 evidence-mapping

```text
请修改 01_Skills/evidence-mapping/SKILL.md。

修改原因：在 Matter 2026-008 的测试中，Skill 只提取了支持我方的聊天记录，没有识别同一对话中对我方不利的上下文。
证据位置：07_Evals/results/EVAL-20260901-002 和该 Skill 的测试用例 EM-006。
目标：对聊天记录进行上下文完整性检查，分别列出支持、反驳与语义不完整的片段；关键对话不得只引用单条消息。

请先判断这是通用证据映射原则还是仅限聊天记录的参考规则；做最小必要修改，新增可复现 EM-006 的回归测试，比较修改前后 Evidence Omission、Adverse Evidence Recognition 和 Critical Error。不要把 2026-008 的客户名称或原文写入 Skill。
```

## 你如何告诉我“先审查、不修改”

```text
请审查 01_Skills/[skill-name]，重点看 [问题]。目前只诊断和提出最小修改方案，不改文件。请引用具体文件位置，并判断该问题应改 Skill、reference、template、tool 还是 Matter 指令。
```

## 你如何告诉我“直接修改”

```text
请按 docs/HOW_TO_MODIFY_SKILL.md 直接修改 01_Skills/[skill-name]。问题、证据和目标如下：[填写]。完成代码/文件修改、回归与变更日志，但不要激活、提交 Git 或对外上传；最后把需要我决定的事项集中列出。
```

## 版本建议

- `PATCH`（0.1.0 → 0.1.1）：错别字、失效链接、无行为变化的澄清；
- `MINOR`（0.1.0 → 0.2.0）：新增规则、输出或明显行为变化，兼容原用途；
- `MAJOR`（1.x → 2.0）：适用范围、输入输出或决策逻辑发生不兼容变化。

版本号不能替代 Eval 和律师批准。
