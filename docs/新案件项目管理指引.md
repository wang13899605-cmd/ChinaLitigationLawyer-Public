# 新案件项目管理指引

版本：v1.0｜更新日期：2026-10-04｜适用：本机 `ChinaLitigationLawyer` 工作流

## 一、推荐的组织方式

**真实案件：一个案件文件夹 + 一个对应的 Codex 本地项目。** 同一案件可以有多条对话，但不要把多个客户、多个案件混在一条长对话里。`ChinaLitigationLawyer` 母项目主要用于维护通用规则、Skills、模板和测试；案件项目主要用于办理该案。

案件项目不需要复制一套工作流。每次明确调用全局入口 `$china-litigation-workflow`，它会从母项目读取**当时已保存的最新本地版本**。案件事实、证据、律师决定和文书版本则保存在该案件文件夹，不以聊天记录为唯一载体。

这是**工作组织和降低串案风险的方式，不是技术上的绝对访问隔离**。实际可访问范围仍受本机文件权限、Codex 项目所附文件夹及运行环境权限控制；不得仅因分了项目就假定其他案件文件无法被读取。

## 二、新案启动：六步

1. **确定唯一案件目录。** 优先在 `<FRAMEWORK_ROOT>\08_Cases\` 下建立新 Matter；若已有律所受控目录，也可使用该目录。一个案件只指定一个正式 `MATTER_ROOT`，不在两处并行维护活动副本。
2. **放置材料。** 将收到的文件保存在案件目录或明确的收件目录，保留客户原始文件名和目录关系。尚未规范化的案件可先把材料放入临时收件区，首轮请 Codex 登记并复制到 `00_Original`；不要自行覆盖旧材料。
3. **在 Codex 桌面应用中新建本地项目。** 将该案件目录设为项目的主文件夹。不要把其他案件目录批量附加到此项目；也无需将母项目附加为第二文件夹来“继承”工作流。
4. **从案件项目新开对话，明确调用入口。** 复制下方“首轮接案指令”，填写路径及已知信息。未知项可以留空，入口会根据材料和接案流程补问必要问题。
5. **核对首轮结果。** 先看材料索引、事实与证据缺口、期限、拟制作文书及 `LAWYER_QUESTIONS.md`。只有需要律师判断的实质问题才答复；答复后要求写入 `LAWYER_DECISIONS.md` 并更新受影响成果。
6. **继续办理。** 同一案件的后续任务留在该项目。单一对话过长时，可以在该项目新开对话，并再次给出同一个案件绝对路径；不必搬运旧聊天全文。

### 首轮接案指令（复制后填写）

```text
调用 $china-litigation-workflow，处理案件文件夹：<案件文件夹的绝对路径>。
原始材料位于：<材料目录的绝对路径；如已在案件目录中，写明具体子目录>。
客户：<名称或“请先从材料识别并向我核对”>。
我方诉讼地位：<原告/被告/第三人/尚不确定>。
对方：<名称或尚不确定>。
案件概况与客户目标：<简述；不清楚的可写“请先阅读材料后向我提问”>。
当前程序阶段：<尚未起诉/一审/二审/执行等>。
最近期限：<具体日期、来源；未知则写“未知，请核查材料”>。
本次任务：先完成接案、材料登记、事实与证据初步整理、期限识别及文书计划；需要律师判断的问题集中向我提出。不得对外提交或发送文件。
```

若案件目录尚未建立，可以改为：

```text
调用 $china-litigation-workflow，在母项目默认的 08_Cases 位置新建 Matter。
原始材料路径：<收件目录的绝对路径>。
请先向我核对案件编号、客户、我方地位、对方、目标、程序阶段和最近期限，再完成接案。
```

在第二种情况下，**先取得新 Matter 的确切路径，再将该目录设为单案项目的主文件夹**。不要自己猜测生成的目录名。

## 三、后续任务怎么开对话

- **同一任务的修改与补充：**优先接续原对话，例如“我已回答Q-0003，请更新利息测算和起诉状”。
- **同案的新阶段或独立成果：**可以在该案件项目中新开对话。开头仍写“调用 `$china-litigation-workflow`，继续处理案件文件夹：`<同一绝对路径>`；先读取本案现有记录和未决律师问题；本次任务是……”。
- **其他案件：**进入另一个案件项目，不沿用前案对话。通用工作流需要调整时，到母项目提出修改，不把某案事实写进通用 Skill 或模板。

### 补充证据指令

```text
调用 $china-litigation-workflow，继续处理案件文件夹：<绝对路径>。
新一批材料位于：<新证据目录的绝对路径>。
请先核对文件并向我询问本批次来源、实际接收日期和可选说明；我回答后登记 Evidence ID，分析对事实、请求、期限和现有文书的影响。不要覆盖原件或旧版本。
```

### 收到法院通知或新任务指令

```text
调用 $china-litigation-workflow，继续处理案件文件夹：<绝对路径>。
新文件位于：<绝对路径>。请登记文件和实际接收时间，核对其是否变更原通知，更新期限、开庭安排及受影响文书；需要我确认的事项单列。
```

## 四、保存位置与版本规则

| 内容 | 保存原则 |
|---|---|
| 原始材料 | 当前 Matter 的 `00_Original`；只读保留，不直接修改或覆盖。 |
| 材料索引与接收记录 | 当前 Matter 的 `01_Index`。 |
| 分析、时间轴、计算与法源 | 当前 Matter 对应的事实、证据、法律和分析目录；能追溯到材料与来源。 |
| AI 文书草稿 | 当前 Matter 的 `08_Drafts`，保留版本及 `AI_DRAFT` / `REVIEW_REQUIRED` 状态。 |
| 律师问题及决定 | 当前 Matter 根目录的 `LAWYER_QUESTIONS.md`、`LAWYER_DECISIONS.md`。 |
| 通用规则、Skills、模板 | 母项目 `ChinaLitigationLawyer`；单案项目只调用，不复制一份作为长期分叉。 |

入口会重新读取母项目最新已保存文件，**但最新不等于已验证**：仍要遵守各 Skill 的状态、母版适配、来源核验、逐页自检和律师审批门槛。未明确授权时，不提交法院、不发送客户或第三方，也不将 AI 草稿标成律师已批准。

## 五、保密与同事共用须知

- 本仓库及全局 Skill **不会因转发本文件而自动出现在同事电脑**。同事使用前，应在其设备上克隆仓库、配置入口 Skill、权限和私有存储路径，再验证入口是否能读取规则与模板；详见根目录 `INSTALL.md`。
- 不把客户材料、Matter 文件夹或包含真实案件资料的 Git 内容发到公共仓库；不因项目名称为“私有”就省略律所数据安全审查。
- 如案件目录在律所盘、同步盘或另一 Git 仓库，首轮先核对访问权限、同步、备份与提交范围；不要自行开启云同步或上传第三方服务。
- 仅在任务所需范围内处理案件材料。对外文件必须由律师确认具体版本与用途；“已起草完成”不等于“已批准提交”。

## 六、何时不必另建项目

纯演示、短时测试或只讨论通用工作流时，可直接在 `ChinaLitigationLawyer` 母项目下新开对话。但真实案件如果将长期办理、持续补证或由多人协作，优先采用单案本地项目。
