# ChinaLitigationLawyer 律师使用手册

## 你平时只需要记住七个入口

1. 综合可视化工作台：双击根目录的`启动工作流网站.cmd`
2. 可编辑流程图与Skill编辑器：双击根目录的`启动可编辑流程图.cmd`
3. 跨项目调用：`$china-litigation-workflow`
4. 默认新案件：`08_Cases/`
5. AI 需要你决定的问题：某个 Matter 的 `LAWYER_QUESTIONS.md`
6. 你的决定：同一 Matter 的 `LAWYER_DECISIONS.md`
7. 系统改进：`01_Skills/`、`04_Experience/`、`05_Templates/`、`06_Gold_Standard/`、`07_Evals/`

其余目录主要由 Codex 按规则维护。你不需要手工建立几十个文件，也不需要写代码。

网站中的工作流、Skill和模板清单均从本项目权威文件实时读取。你可以在“反馈与迭代”中登记问题，然后把网页生成的指令交给Codex；Codex完成规则或Skill修改、版本记录和回归后，刷新网页即可看到更新。模板上传会先进入`05_Templates/_Incoming/`，不会未经脱敏、版式核验、索引登记和律师确认就自动启用。

独立的可编辑流程图网站使用`http://127.0.0.1:4327/`：流程图按BPMN 2.0制图语义展示，总览使用事件、折叠子流程和顺序流，阶段明细使用律师/AI两条Lane及原有Task；在“流程图”中可拖动阶段、修改图示显示名称和备注，在“Skill库”中可直接编辑现有`SKILL.md`。Skill保存前必须填写新版本、原因和摘要并通过检查；网站会备份原文件并登记日志，但新版本仍是`regression_pending`，不是已验证版本。需要新增Skill、修改流程矩阵原始动作、增加真实Gateway分支或完成回归时，仍应直接交办Codex。该网站是仅在本机运行的工具，不会随网址永久在线；每次电脑重启或服务停止后，重新双击`启动可编辑流程图.cmd`即可。启动器会先检测服务，必要时在后台启动并通过健康检查后再打开网页；重复双击不会另起冲突服务。

## 第一次要做什么

打开 `docs/LAWYER_REVIEW.md`，处理七项律师审阅事项。这些事项涉及云端 AI、业务范围、AI 何时必须问你、对外审批、律所数据规则、研究来源和脱敏标准。未确认前系统使用保守默认值。

你可以直接对 Codex 说：

```text
请阅读 docs/LAWYER_REVIEW.md。逐项向我解释 LR-01 至 LR-07 的当前默认值、风险和可选方案。一次只讨论一项；我确认后，把决定写回该文件，并同步修改受影响的 Rules、AGENTS.md 或文档，记录到 10_Logs/system_change_log.md。不要修改无关内容，不要自动提交 Git。
```

## 每个新案件如何开始

默认建议把新Matter放在 `08_Cases/`。如果案件已有其他受控本地目录，或你希望把案件文件夹单独作为Codex项目，也可以保留外部路径并明确调用：

需要一份可以直接复制填写的标准接案表时，使用`docs/NEW_MATTER_INTAKE_TEMPLATE.md`。你只需回答其中的简单问题并提供材料路径；不清楚的内容可以写“请从材料识别”，Codex应先读材料，再只补问实质性缺口。

```text
调用 $china-litigation-workflow，处理案件文件夹：<案件绝对路径>。
本次任务是：<具体任务>。
```

两种方式都调用同一套最新工作流；区别仅在Matter存放位置。完整说明见 `docs/HOW_TO_INVOKE_WORKFLOW_ANYWHERE.md`。

不要只说“帮我分析这个案子”。用一个 Matter 承载全部工作。例如：

```text
请新建 Matter。

客户：A公司；我方代理原告。
对方：B公司。
目标：追回设备货款约480万元，并尽可能尽快实现回款。
材料来源：D:\客户材料\A公司诉B公司。

请先阅读 AGENTS.md 和 00_System/Workflows/new_matter.md；从 08_Cases/_MATTER_TEMPLATE 创建唯一编号的 Matter。只复制来源材料，不得移动、重命名或修改来源原件。先建立材料索引并做 Initial Case Assessment。真正需要我专业判断的问题写入 LAWYER_QUESTIONS.md，但继续完成不受影响的工作。任何对外发送或提交都要等我明确确认。
```

Codex还会在Matter建立时一次性询问是否启用主动期限提醒，以及接收人、提醒方式和覆盖期限类型。你也可以在首条指令中直接说明，例如：“主动提醒：启用；接收人：Albert Wang；方式：当前任务；范围：法院/仲裁机构指定期限及救济期限。”未确认时只建立期限台账，不创建主动提醒。

Codex 应当依次完成：Matter 建立 → 材料索引 → 程序文件和期限登记 → 派生文本 → 事实与时间线 → 证据映射 → 请求/抗辩候选与要件 → 主位/备位/条件性方案比较 → 管辖候选与异议分析 → 计算 → 法律研究 → 风险与对方观点 → 补证建议 → 文书计划 → 匹配 Word 模板并起草当前必要文件 → 逐页版式与内容质检 → Lawyer Questions → 初步分析。请求权分析须先给出AI推荐和完整备选，不把未经分析的策略问题直接抛给律师；最终请求、抗辩、反诉、承认、放弃和对外案件理论仍由律师决定。当前18个项目业务Skill已经激活，Codex应按任务自动选择真正适用的Skill；它们仍处于真实案件持续测试阶段，自动调用不等于律师验证或对外批准。

详细流程见 `docs/HOW_TO_RUN_MATTER.md`。

## 客户补充新证据时怎么做

正式办案优先使用文件夹，不把对话附件当作长期案卷。为每一批新证据建立独立目录：

```text
08_Cases/<Matter>/00_Original/Client_Supplements/YYYY-MM-DD_batch-N/
```

保留客户原始文件名和目录关系；不得覆盖上一批同名文件，也不要把OCR、批注、改名件或摘要放入该目录。随后只需要告诉Codex Matter和绝对路径：

```text
请处理Matter：08_Cases/<Matter>。
客户补充证据位置：<绝对路径>。
请执行新证据增量更新。
```

Codex核对Matter和路径后，会自动一次性询问本批次来源/接收方式、实际接收日期和可选说明。你回答后，Codex再完成正式证据登记、去重、Evidence ID、证据审查及影响传播。已经提供的字段不会重复询问；没有批次说明可答“无”或留空。若当前Matter尚未记录材料处理授权，Codex会在同一次问题中一并确认，不单独再问一轮。

直接在对话中上传适合少量、紧急或尚未建立Matter的临时材料。除非该附件同时保存进受控Matter目录，否则Codex必须说明其尚未进入正式原始证据库。当前LR-01仍要求真实客户材料获得具体Matter的处理授权；工作模式提供本地文件操作能力，但不替代客户授权或律所数据规则。

## 收到新传票、通知或其他程序文件时怎么做

把文件保存到当前Matter的 `00_Original/` 下，不覆盖旧通知，然后告诉Codex：

```text
请处理Matter：08_Cases/<Matter>。
新程序文件位置：<绝对路径>。
请执行程序文件与期限增量更新。
```

如果你没有一并说明，Codex会自动一次性询问来源/接收方式、实际接收日期和时间、是否变更或替代旧通知、可选说明。回答后，Codex会登记新旧版本，核验期限规则，进行确定性计算和独立复核，更新庭审信息、期限台账、文书计划及已授权的提醒。开庭时间变更、冲突送达日、可能逾期、7日内临期、诉讼时效/除斥期间以及可能丧失权利的事项会提交律师判断。

主动提醒依赖桌面应用的计划任务能力；处理本地项目时电脑需保持开机、应用需运行且项目目录可访问。即使启用了提醒，也应以Matter内 `DEADLINE_REGISTER.yaml`、`REMINDER_REGISTER.yaml` 和完成凭证为审计依据，不能把通知本身当作期限记录。产品能力说明见 [OpenAI Scheduled tasks](https://learn.chatgpt.com/docs/automations)。

## 你如何回答 AI 的问题

打开当前 Matter 的 `LAWYER_QUESTIONS.md`。不要只回复“按你的建议”，尽量说明：选择、适用范围、理由/客户情况、是否只限当前阶段。

然后告诉 Codex：

```text
我已回答 LAWYER_QUESTIONS.md 中的 Q-0003 和 Q-0005。请把答案结构化记录到 LAWYER_DECISIONS.md，标明日期、范围和受影响输出；更新问题状态，并只重跑受这两项决定影响的分析和草稿。列出修改前后发生的实质变化。
```

## 如何把一次办案变成长期能力

案件结束后，不把整个案件直接扔进“知识库”。按以下闭环处理：

真实案件 → 你的纠正 → 法院/仲裁庭/客户反馈 → Matter 内复盘 → 脱敏 Experience 草稿 → 律师验证 → 判断是否需要修改 Skill → 用 Gold Standard 和回归集评测 → 只保留经验证的修改。

安装后，当前18个项目业务Skill可用于受控测试。后续任务由Codex自动选择全部真正适用的Skill；Skill尚未完整测试不构成跳过理由。你发现问题时可直接指出应修改的环节；Codex自行发现问题时，应向你报告具体Skill、影响、临时处理和建议修改范围。除非你已经要求修改Skill，Codex先报告并继续不受影响的案件工作，不静默改写通用规则。

## 如何管理文件夹

- `00_System`：少改。只有跨案件、跨 Skill 的稳定规则才进入这里。
- `01_Skills`：一个稳定任务一个 Skill；先测试，后启用。
- `02_Public_Knowledge`：只放可核验公开来源和索引，不放客户信息。
- `03_Private_Knowledge`：放你的一般方法论，不放未脱敏案件复盘。
- `04_Experience`：必须来自真实案件、可追溯、先匿名化、再由你验证。
- `05_Templates`：Word 是版式母版；`TEMPLATE_INDEX.yaml` 决定自动选用。模板事实永远不是新案件事实。新增/更新方法见 `docs/HOW_TO_ADD_OR_UPDATE_TEMPLATES.md`。
- `06_Gold_Standard`：放你认可的高质量成果；胜诉不自动等于金标准。
- `07_Evals`：用真实任务判断系统是否变好，不能凭感觉。
- `08_Cases`：真实案件，一案一目录，默认不进入 Git。
- `09_Tools`：可复算的计算、解析和核对工具。
- `10_Logs`：记录为什么改、改了什么、验证结果和是否保留。

庭审周期现有 `prc-hearing-preparation-and-record v0.1.1 draft`：新开庭安排先交G4确认，正式开庭前分别准备庭审提纲与法律法规汇编，法条栏目逐条照录经核验的完整原文；庭后由律师上传记录，AI再整理来源、庭审事件、笔录差异、期限及补充文书。该Skill已经激活用于真实案件持续测试，但尚未通过完整历史Matter行为回归，不能把自动调用或`draft`状态等同于律师已验证。

## 每月维护建议

每月一次即可：

1. 检查 `LAWYER_QUESTIONS` 是否仍有长期未处理的高优先级问题；
2. 审核 `04_Experience/pending_review`，决定验证、退回或删除（删除前另行确认）；
3. 查看 Skill 修改是否有回归结果，是否出现“越改越长但指标不变”；
4. 核验高频法律来源的 `last_checked`；
5. 检查是否有真实案件材料误入 Git；
6. 将已结 Matter 按律所留档制度处理，不由 AI 自行删除。

## 什么时候直接找我

- “在这个 Matter 里完成某项具体工作”：直接说明 Matter 名称、目标和截止时间。
- “新建/修改 Skill”：按 `HOW_TO_CREATE_SKILL.md` 或 `HOW_TO_MODIFY_SKILL.md` 的标准指令说。
- “系统规则是否合理”：让我先审查，不授权修改时我只报告问题。
- “请直接修改”：明确文件或目标，我会修改、验证、报告；对外发送、删除和重大策略决定仍需单独授权。
