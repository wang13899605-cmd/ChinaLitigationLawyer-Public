# 从任意 Codex 项目调用本工作流

## 入口

安装并配置全局入口 Skill 后，可使用 `$china-litigation-workflow`。它只在律师明确调用时运行，不自动介入其他项目；安装方法见根目录 `INSTALL.md`。

标准指令：

```text
调用 $china-litigation-workflow，处理案件文件夹：<案件绝对路径>。
本次任务是：<需要完成的事项>。
```

入口本身不复制规则、Skills、模板或工具。每次调用均实时读取：

```text
<你克隆本仓库后的本地绝对路径，即 FRAMEWORK_ROOT>
```

因此，母项目内已保存但尚未 Git 提交的更新也是下一次调用所使用的最新本地版本。

## 两种存放方式

### 默认：母项目管理

```text
<FRAMEWORK_ROOT>\08_Cases\<Matter>
```

适合绝大多数新案件。其优势是原生继承项目指令、标准目录、Matter母版和现有Git忽略规则，路径最短、出错面最小。

新案最好直接说：

```text
调用 $china-litigation-workflow，在默认08_Cases位置新建Matter。
原始材料路径：<收件或暂存目录绝对路径>。
客户：……；我方地位：……；对方：……；案件概况：……；客户目标：……；程序阶段：……；最近期限：……。
请按最新工作流完成接案、材料登记、分析和当前必要文书；需要律师判断的问题集中提交。
```

Codex从最新 `_MATTER_TEMPLATE` 建立唯一Matter，并把获准材料复制到 `00_Original`；不移动或修改来源文件。

### 外部存放

适合案件已经存在于律所盘、个人受控案件库、容量较大的存储位置，或者希望把该案件目录单独保存为Codex项目的情形。

```text
调用 $china-litigation-workflow，处理案件文件夹：D:\案件\<Matter>。
本次任务是：……
```

此时案件成果写入指定目录，共享规则、Skills、模板和工具仍从母项目读取。首次调用会检查并补齐Matter结构，同时核对是否存在其他Git跟踪、云盘同步、权限或保密风险。

## 选择建议

- 没有既有存储要求的新案件：优先放在 `08_Cases`。
- 已经有稳定律所目录、备份制度或单案独立项目需求：可以使用外部路径，核心工作流不减损。
- 不建议把同一Matter同时在两处作为活动副本；只保留一个正式 `MATTER_ROOT`，其他位置仅作为有来源记录的材料来源或备份。
- 无论放在哪里，聊天记录都不是唯一案件记录；事实、证据、律师决定、期限、计算和文书版本应写回Matter目录。

## 恢复已有案件

在新Codex任务中只需再次明确调用并给出同一绝对路径：

```text
调用 $china-litigation-workflow，继续处理案件文件夹：<案件绝对路径>。
请先读取该Matter现有记录和未决律师问题，再完成：<任务>。
```

入口会重新读取母项目最新版本和当前Matter状态，不依赖上一段聊天记忆。
